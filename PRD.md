# PRD — White-Label AI App Vault Landing Page

## 1. Ringkasan Produk

**Nama proyek:** White-Label AI App Vault
**Tipe produk:** Mobile-first sales landing page
**Tujuan utama:** Menjual lisensi white-label untuk 13 aplikasi AI marketing yang dapat direbrand dan dijual kembali oleh buyer menggunakan brand mereka sendiri.

Landing page tidak menjual aplikasi sebagai “tool untuk dipakai sendiri”, melainkan sebagai:

> Paket produk aplikasi AI siap rebrand untuk advertiser, owner agency, mentor marketing, creator educator, operator marketplace, dan owner komunitas.

Buyer membeli hak untuk mengemas aplikasi sebagai produk branded milik mereka, lalu menjual aksesnya kepada audiens, customer, member komunitas, atau klien mereka.

---

# 2. Latar Belakang dan Masalah

Target buyer biasanya sudah memiliki salah satu aset berikut:

* audiens media sosial
* komunitas Telegram, WhatsApp, Discord, atau Facebook Group
* klien agency
* murid course atau mentoring
* database leads
* channel affiliate
* reputasi di niche marketing tertentu

Namun mereka belum memiliki produk digital berbentuk aplikasi yang:

* terasa premium
* memiliki visual produk nyata
* dapat diberi nama dan identitas sendiri
* mudah dibundling dengan course, komunitas, atau jasa
* dapat dijual berulang tanpa selalu menukar waktu dengan uang
* dapat menjadi lead magnet atau upsell

Membangun aplikasi AI dari nol membutuhkan desain, coding, prompt engineering, testing, dan maintenance. Produk ini mempersingkat proses tersebut dengan menyediakan 13 aplikasi yang siap direbrand.

# 9. App Launcher Requirement

## Objective

Menunjukkan bahwa bundle berisi 13 aplikasi nyata tanpa memakai mockup palsu atau preview UI yang tidak sesuai.

## Desktop Layout

* Grid 3 kolom.
* Di sisi kanan ada detail panel.
* User klik app card untuk mengganti detail panel.
* Card memperlihatkan:

  * icon
  * nama aplikasi
  * subtitle pendek

## Mobile Layout

Gunakan model app launcher.

### Layout

* 4 kolom.
* Icon kecil + nama aplikasi saja.
* Tidak tampilkan subtitle di card.
* Card berbentuk kotak.
* Detail aplikasi muncul di bawah grid.
* Tidak boleh sticky karena berpotensi menutup launcher.
* Setelah user memilih icon, halaman scroll halus ke detail panel.

### Launcher Header

Tampilkan instruksi jelas:

> Pilih aplikasi dari launcher di bawah.

Subtext:

> Ketuk icon aplikasi untuk melihat positioning dan contoh produk yang bisa Anda jual dengan brand sendiri.

Tampilkan chip:

> Preview aktif: ADSprint

Chip berubah mengikuti aplikasi yang dipilih.

### Active State

Aplikasi aktif wajib memiliki:

* border atau outline lime.
* active indicator dot.
* contrast yang kuat.
* tidak menggunakan badge teks panjang seperti “aktif” jika membuat card terlalu penuh.

### Accessibility

* Semua card menggunakan `<button>`.
* Keyboard accessible.
* Focus ring jelas.
* `aria-live` untuk detail panel.
* Nama app harus terbaca screen reader.

# 11. Lead Capture Flow

## Trigger

Lead form dibuka dari:

* Hero CTA.
* CTA di final section.
* Sticky mobile CTA.
* Optional CTA setelah app launcher.
* Optional CTA setelah niche pack.

## Required Fields

* Nama
* Email
* Nomor WhatsApp
* Niche utama
* Optional: jumlah audiens atau tipe bisnis

## Niche Dropdown

* Advertiser / Media Buyer
* Agency
* Mentor / Course Creator
* Affiliate / Creator
* Marketplace Seller / Mentor Seller
* Web Designer / Funnel Builder
* Community Owner
* Other

## Hidden Fields

* UTM source
* UTM medium
* UTM campaign
* UTM content
* UTM term
* Referrer
* Landing page URL
* Timestamp
* Device type
* Browser language
* Form source / CTA location

## Submission Success State

Setelah submit:

1. Tampilkan success confirmation.
2. Jika WhatsApp URL sudah tersedia, arahkan ke WhatsApp setelah 2–4 detik.
3. Simpan lead ke backend.
4. Kirim event `Lead`.
5. Simpan attribution data.

Contoh confirmation:

> Terima kasih. Detail akses dan jalur pack yang paling cocok akan kami kirimkan melalui WhatsApp atau email.

# 12. Mobile Sticky CTA

## Objective

Mengurangi kehilangan visitor dari traffic Meta Ads yang mayoritas mobile.

## Behavior

* Muncul setelah visitor scroll melewati hero.
* Tetap berada di bawah layar.
* Tidak boleh menutupi form input, modal, cookie notice, atau navigation.
* Hidden saat modal lead terbuka.
* CTA:

  * `Cek Lisensi White-Label`
  * atau `Ambil Akses Awal`

## Mobile Design

* Full width.
* Tinggi minimum 52px.
* Background dark atau lime dengan contrast tinggi.
* Shadow untuk membedakan dari content.
* Safe-area padding untuk iPhone.

# 14. Technical Architecture

## Frontend

Recommended stack:

* Vite
* Vanilla HTML
* Vanilla CSS
* Vanilla JavaScript
* Static content data module
* No React dependency for V1 unless AI agent already has a strong React workflow

Reason:

* Faster load.
* Smaller bundle.
* Easier deployment.
* Easier maintenance.
* Suitable for a conversion landing page.
* Avoid unnecessary hydration.

## Hosting

* Cloudflare Pages
* Production domain custom domain
* Preview deployments via Git integration

## Backend

Use Cloudflare Pages Functions or Cloudflare Worker for:

```text
POST /api/lead
```

Responsibilities:

* Validate request payload.
* Reject invalid email/phone.
* Honeypot check.
* Rate limit by IP.
* Store lead in destination.
* Forward lead to Google Sheets, CRM, webhook, Telegram, or email provider.
* Return success response.
* Do not expose API secrets to browser.

## Lead Storage V1

Preferred options:

1. Google Sheets via Apps Script webhook.
2. Airtable webhook.
3. Notion database webhook.
4. Supabase table.
5. Cloudflare D1 only if later needed.

Recommended V1:

* Google Sheets for operations simplicity.
* Optional backup into Cloudflare D1 or Supabase after product validation.

## Environment Variables

```env
LEAD_WEBHOOK_URL=
WHATSAPP_REDIRECT_URL=
META_PIXEL_ID=
GA4_MEASUREMENT_ID=
GTM_CONTAINER_ID=
TURNSTILE_SITE_KEY=
TURNSTILE_SECRET_KEY=
```

Never expose secrets in frontend code.

# 15. Anti-Spam and Security

## Required

* Honeypot input hidden from normal users.
* Cloudflare Turnstile optional but recommended.
* Basic IP rate limit.
* Input sanitization.
* Server-side validation.
* No sensitive secrets in frontend.
* CORS restricted to production domain and preview domain as needed.
* Avoid logging full personal data in browser console.
* Avoid sending lead data to multiple third parties without consent.

## Form Validation

Required validation:

* Name: minimum 2 characters.
* Email: valid email format.
* WhatsApp: Indonesian/international phone normalization.
* Niche: required.
* Honeypot: must stay empty.

# 16. Performance Requirements

## Mobile Target

* Optimized for Meta Ads traffic.
* Prioritize first contentful paint.
* Avoid large JS libraries.
* Avoid iframe preview for 13 applications.
* Avoid autoplay video in V1.
* Avoid loading unnecessary app screenshots above the fold.
* Use `font-display: swap`.
* Use WebP or AVIF for future real screenshots.
* Lazy load below-the-fold images.
* Respect `prefers-reduced-motion`.

## Design Constraints

* No horizontal overflow at 320px width.
* No button smaller than 44px touch target.
* No text smaller than 10px for primary readable content.
* Body text minimum 13–14px on mobile.
* Form input minimum 16px on mobile to avoid iOS zoom.
* Use safe-area padding for sticky CTA and modal.
